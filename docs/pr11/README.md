# Daily Briefing / Data Observation v1

최신 main `0737448` 기반. `feat/daily-briefing-analyst-note-v1`.

## 기존 구현과 변경 이유

기존 엔진은 게시 게이트를 통과한 Newsroom에서 최근 24시간 상위 5개를
`briefing.json`에 덮어썼고 날짜별 기록은 없었다. 홈 관찰 카드는 고정 날짜와
문구였다. 기존 discovery/rights/relevance/Indirect/공시·통계 분리 정책은
수정하지 않고 **게시 이후 브리핑 선정·보관**만 독립 모듈로 교체했다.

## 브리핑

- 국내 직접 관련 우선 → 같은 우선순위 내 카테고리 다양성 → 발행시각 순.
  최대 5개이며 0~4개일 때 채우지 않는다. reference/통계/공시/보관전용 제외.
- 명시적 시각·시간대가 있는 검증된 발행시각만 24시간 판정. 날짜만 제공되거나
  미검증/미래/24시간 이전이면 제외. 발견/생성시각을 발행일로 쓰지 않는다.
- 기존 엔진 중복 제거 이후 URL 및 보수적인 제목 유사도 0.90 이상을 추가 제외.
  의미 기반 사건 판별을 주장하지 않으며 서로 다른 제목의 동일 사건은 남을 수 있다.
- 공개 기사 필드는 제목/매체/발행일/카테고리/키워드/URL의 기존 6개만 유지.
  본문·이미지·AI 요약·선정 근거는 공개하지 않는다.
- 현재 후보와 보관된 날짜별 브리프를 선택한다. 복사는 선택된 화면의 메타데이터만
  사용한다. 비어 있으면 복사할 뉴스가 없다고 표시한다. 전송 성공 메시지는 없다.
- 생성일, 개별 발행일, 해당 브리프의 수집 성공시각, 뉴스 DB 최근 수집 성공,
  상태를 구분한다. 과거 브리프·오래된 생성 후보·갱신 실패도 명시한다.
- 스키마4 기존 briefing.json은 읽기 호환. 새 출력은 schema_version 5.
  기존 파일의 누락된 과거 수집시각은 임의 보충하지 않고 미기재라고 표시한다.

## 영속화 및 시간 정책

| 위치 | 내용 |
|---|---|
| `site/data/briefing.json` | 매 성공 수집 때 갱신하는 현재 후보 |
| `site/data/briefing_archive.json` | 10:30 KST 이후 첫 성공 때 생성한 날짜별 불변 스냅샷 |
| `collector_state/briefing_selection.json` | 해당 날짜 최초 선별의 ID·판정·우선순위·발행시각·내부 근거 |
| `collector_state/briefing_latest_selection.json` | 최신 후보 선별의 내부 근거 |

- 10:30 이전 실행은 현재 후보만 갱신. 이후 같은 날짜 재실행은 일별 기록을
  중복 추가하거나 덮어쓰지 않는다. 0건 기록도 당시 상태 그대로 보존한다.
  나중에 새 기사가 생기면 현재 후보에는 반영하되 최초 일별 기록은 유지한다.
- 수집 전체 실패는 기존 엔진의 실패 분기로 현재/아카이브를 바이트 그대로 보존.
- JSON 파일별 atomic replace. 내부 일별 근거를 먼저 저장하여 중단 후 재실행해도
  날짜 키로 중복 방지. 전체 뉴스/브리핑 파일 묶음의 다중 파일 트랜잭션은 아니다.
- 운영 기록의 내부 분리는 Pages 배포 경로 밖이라는 뜻이며 비밀정보 저장소가 아니다.
  기존 워크플로의 Git 원장 보존 방식을 사용하므로 개인정보·본문·비밀 키를 넣지 않는다.
- 기존 아카이브가 손상되면 비워 덮지 않고 오류 종료한다.
- live/fixture 보관 파일을 섞지 않는다. 인공 데이터는 Python 임시 경로 및 격리된
  브라우저 route에만 존재하며 실제 site/data에 테스트 결과를 저장하지 않는다.
- **이 PR에 실제 과거 아카이브를 생성하거나 기존 DB를 변경하지 않았다.**
  보관은 병합 후 최초 성공 실행부터 누적한다. 보관 전의 과거 기록은 만들지 않는다.
- `.github/workflows/collect.yml`의 기존 2시간/10:30 스케줄, 공유 publish 잠금,
  site/data 및 collector_state/*.json 커밋, Pages site 배포를 그대로 사용한다.
  새 파일도 기존 glob에 포함되므로 실행 종료 후 Git에 보존되고 공개 원장만 배포된다.
  운영 일별 생성/배포는 아직 실행되지 않았으며 완료로 주장하지 않는다.

## Data Observation / 편집 의견

- 홈의 고정 `24 OCT 2026` 문구를 삭제하고 공개 Macro 검증 데이터만 사용한다.
- 연결된 명 단위 월간 입·출국 및 5개 국적 지표만 명시적 allowlist로 허용.
  공식파일검증 상태, 최신 관측값/시계열 일치, 정수·단위·기준월을 확인한다.
- 월 실적, 전월/전년동월비, 연초 누적/전년동기비와 같은 기준월 국적별 값을 표시.
  누락 비교는 비교 자료 없음, 누적 월 누락은 계산 생략. 공식 출처·공표/수집시각·
  잠정/확정 미표기와 정정 건수도 표시한다. 실제 확인한 출처와 값은 verification.json.
- Macro render의 읽기 전용 후크로 새 검증값과 오류/이전값 보존 상태를 반영한다.
  Macro 원장/정정/승인 게이트는 변경하지 않는다. 데이터가 없으면 관찰 불가.
- TOURGO/관광수입/지출/수지/소비는 입력에서 제외한다. 방문객 증가에서 수입·
  1인당 소비·지역 소비의 증가를 추론하지 않는다. 뉴스 내용도 입력하지 않는다.
- **Data Observation은 자동 사실 관찰**, **Analyst's Note는 승인된 편집 의견**으로
  명시한다. 현재 승인된 편집 의견은 없으며 수동 노트 작성/승인 기능을 만들지 않았다.
  가상 분석가·AI 해석·전망을 넣지 않는다. 향후 노트는 작성/승인일·기준월·공식
  출처·승인 상태와 유효기간을 가진 별도 검토 절차 없이는 공개하지 않아야 한다.

## 검증

- Python 전체 **221개 통과** (기존 210 + 브리핑 신규 11).
- 브라우저 7개 스위트 통과: home, newsroom, reports, macro, ui-polish, ui-2,
  briefing-observation. UI polish 28 route/width 조합.
- 요구 사례: 5개 이상/1~4개/0개, 날짜만 있는 기사, 중복, 수집 실패·기존 파일
  보존, 날짜별 재실행, fixture/live 분리, 손상 원장 보호, 공개 JSON에 선정 근거 미포함.
- 신규 브라우저: 320/390/768/1440px, 과거 날짜 선택·새로고침 유지·복사와 링크,
  빈 후보·갱신 실패, Macro 최신월/값 변경 반영·실패·미승인 금융자료 제외.
- 새 테스트 fixture 화면은 저장소에 넣지 않는다. 아래 비교 화면은 실제 공개 DB만
  사용했다. 현재 실제 브리핑은 0건이며 과거 브리프가 없으므로 빈 상태 그대로다.
- 뉴스 발견·권리·게시 게이트/Research/Macro 원장·데이터 JSON/관광수지 승인 게이트/
  GitHub Actions/로고 바이트 유지. 뉴스 엔진은 import와 게시 후 브리핑 호출만 변경.
  Market Weather 계산 함수 SHA는 main과 동일 (verification.json).
- `git diff --check`, JS syntax checks 통과. 인증키/새 외부 API/본문 수집 없음.
