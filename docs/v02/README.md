## 관련성 판단과 게시 결정

판단은 원문 본문이나 AI 모델이 아닌 RSS 제목·설명에 대한 보수적 규칙입니다. `relevance_label`, `relevance_evidence`에 규칙 버전·신호 필드/용어·영향 대상·결정·이유를 남깁니다. 숫자 `relevance`도 유지해 기존 브리핑 정렬과 호환됩니다.

- **Direct → 게시**: 외래관광객, 여행업 실적, 국제선 증편, 객실 공급, 관광정책·관광사업 등 구체적인 산업 대상을 확인합니다. ‘관광’ 한 단어는 게시 근거가 아니며 ‘관광’이 없는 항공·숙박 뉴스도 대상이 될 수 있습니다.
- **Indirect → 검토 보류**: 다른 산업의 변화와 관광수요·소비·기업·정책 대상이 같은 문장에 나타나면 후보로 분리합니다. 영향 관계 표현이 없거나 추정·부정·서로 다른 문장의 우연한 언급만 있으면 확인 근거로 사용하지 않습니다. 일반 문화·경제 기사에 관광 용어가 등장한다고 Direct로 승격하지 않습니다.
- **Indirect 승인 → 게시**: 원문을 실제로 확인한 편집자가 `relevance_reviews.json`에 승인 기록을 추가해야 합니다. 제목 해시·원문 URL·규칙 버전·유효 검토일·구체적인 영향 설명을 검사합니다. 형식 검증은 사실 검증을 대신하지 않으며 이 작업에서 실제 승인을 만들어 넣지 않았습니다. 현재 approvals는 비어 있습니다.
- **Irrelevant → 제외**: 일반 문화·경제·여가·출퇴근·맛집·개인 후기, 관광 영향이 불명확하거나 부정된 항목은 공개 뉴스와 브리핑에서 제외합니다.

`collector_state/decisions.json`에 성공 출처의 항목별 제목·URL·규칙 근거·게시/보류/제외/날짜 오류 결정을 보관합니다. `collector_state/review_queue.json`은 보류 후보입니다. 둘 다 Pages에 포함되지 않지만 Git에 보존되므로 저장소 접근 권한을 따르며 비밀 저장소는 아닙니다. RSS 설명 문장·기사 본문은 저장하지 않습니다. 날짜·URL 검증에서 탈락한 항목은 관련성 라벨과 최종 게시 여부가 다를 수 있어 이를 별도 결정으로 기록합니다.

### 편집 승인 절차

1. 큐의 후보 및 `relevance_evidence`를 확인하고 원문 링크에서 실제 관광산업 영향을 검토합니다. `evidence_status: explicit_feed_claim`인 항목만 현재 승인 대상입니다. 근거가 불충분한 후보는 보류 상태로 둡니다.
2. 후보 ID를 키로 아래 항목을 `relevance_reviews.json`의 `approvals`에 추가합니다. `title_sha256`은 `src.relevance.title_digest(후보의 title)`의 결과입니다.
3. 승인 파일 변경을 검토·병합한 뒤 기존 자동 수집 또는 main의 workflow_dispatch로 반영합니다. 승인 철회도 같은 파일에서 해당 ID를 삭제합니다. 전체 출처 실패 시 데이터 보존이 우선하므로 승인 변경은 정상/부분 성공 수집에서 반영됩니다.

```json
{
  "schema_version": 1,
  "approvals": {
    "CANDIDATE_ID": {
      "rule_version": "0.2",
      "title_sha256": "EXACT_TITLE_SHA256",
      "evidence_url": "EXACT_ORIGINAL_ARTICLE_URL",
      "reviewed_at": "ISO8601_REVIEW_TIME",
      "reason": "편집자가 확인한 구체적인 관광수요·소비·기업·정책 영향과 근거"
    }
  }
}
```

위 예시는 형식 설명이며 실행 가능한 승인 데이터가 아닙니다. 제목 변경·다른 URL·미래 검토일·규칙 버전 불일치·추정 근거의 승인은 거부합니다. 피드에서 항목이 밀려나도 큐에 남은 45일 내 후보는 승인 후 정상 수집에서 게시할 수 있습니다.

새 카테고리는 관광정책 / 인바운드 / 여행산업 / 항공·숙박 / 문화·트렌드 / 경제·시장입니다. 항공·숙박은 신규 분리 범주이며 실제 수집/마이그레이션 때 내용으로 재분류합니다. UI 매핑은 구형 JSON을 임시 표시하기 위한 것이며 관련성 승인으로 취급하지 않습니다.

첫 정상 또는 부분 성공 실행에서 `schema_version:2`, `rule_version:0.2`로 전환합니다. ID·URL·발행일은 유지합니다. 기존 기록은 원형을 `collector_state/legacy_archive.json`에 보존하고, 재수신 또는 저장된 메타데이터로 재판정합니다. 확인이 불가능하면 원형 보존과 함께 `needs_refetch` 큐에 둡니다. 과거 분류를 근거 없이 Direct라고 표시하지 않습니다. v0.2의 정상 게시 데이터를 출처 장애로 다시 받지 못하면 기존 검증 기록을 유지하고, 승인된 Indirect는 현재 승인 기록을 재확인합니다.

전체 출처 실패 시에는 마이그레이션하지 않고 news·briefing·검토 상태를 바이트 단위로 유지하며 health만 갱신합니다. 실제 운영 JSON은 이 PR에서 덮어쓰지 않았습니다. main의 수집 작업이 병합 후 최신 파일을 입력으로 마이그레이션합니다.

실행 시각과 원본별 결과는 [validation.json](validation.json)에 기록했습니다. 기존 main JSON 3건을 복사한 저장소 밖 검증 디렉터리에서 테스트했습니다.

- 성공 4/7 출처: 서울시 문화·경제·교통·환경, 합계 **80 RSS 항목**.
- 이번 수신에서 Direct **3건** 게시 대상, Indirect **0건**, Irrelevant **77건**. 날짜 등 검증 후 선별 결과입니다.
- 문화 20건 → 문화·트렌드 2건, 경제 20건 → 여행산업 1건, 교통·환경 각 20건 → 0건. 수신 성공과 뉴스 선별 성공을 구분합니다.
- 기존 인바운드 1건은 저장 메타데이터로 재검증하여 유지합니다. 최종 데이터는 **4건**, 중복 재실행 후에도 4건입니다.
- 최종 카테고리: 관광정책 0 / 인바운드 1 / 여행산업 1 / 항공·숙박 0 / 문화·트렌드 2 / 경제·시장 0.

이 분포는 실제 접근 가능한 출처의 한 시점 결과이며 전국 산업 뉴스나 항공·숙박 보도를 충분히 커버한다는 뜻은 아닙니다.

## 오분류·자동화 검증

실제 RSS 검토 중 ‘참여 행사’·‘연결하여 행사’를 띄어쓰기 제거 후 ‘여행사’로 오인하는 문제를 발견했습니다. 단어 경계와 조사 조건을 도입해 일반 친환경 행사·야간 축제의 잘못된 Direct 판정을 제외했습니다. 관광사업을 명시한 웰니스 제목이 설명의 다른 문화 키워드 때문에 제외되는 문제도 수정했습니다. 이 반례들을 합성 사례에 포함했습니다.

- Python **52개 테스트 통과**: 기존 32개는 새 카테고리 기대값만 조정하고 기능 검증을 유지했습니다. 신규 20개는 승인·철회·날짜·근거·이력·마이그레이션·영구 보존 등을 확인합니다.
- 별도 합성 반례 **36건**: Direct 11 / Indirect 8 / Irrelevant 17을 기대대로 분류했습니다. 실제 전체 뉴스에 대한 정확도 측정치가 아닙니다.
- Chromium/Playwright: 실제 JSON 표시·검색·상세의 판단 근거·카테고리 필터·저장·순서 변경·전체 장애 시 기존 표시 보존·브리핑·구형 카테고리 호환을 검증했습니다. JS 오류 0건.
- actionlint v1.7.7 및 `git diff --check` 통과. 기존 CSS 블록은 변경하지 않았습니다.
- 실제 워크플로의 저장 명령을 임시 Git 원격에서 실행하고 새 checkout에서 news·briefing·health와 검토 큐·원형 아카이브·판단 이력을 복원했습니다. Pages artifact는 `site`만 포함합니다.

기존 2시간 간격 및 한국시간 10:30 예약, workflow_dispatch, 중복 제거, 45일 보관·450건 상한, 날짜 검증, Git 커밋 영구 보존과 같은 실행에서의 Pages 배포를 유지합니다. 추가 상태 파일도 Git 커밋과 진단 artifact에 포함하며 편집 승인 변경은 수집을 촉발합니다. PR에서는 테스트만 실행하고 수집·배포는 main에서만 실행합니다.

```bash
python3 -m unittest discover -s tests -v
python3 src/collector.py --dir /tmp/tourism-v02-check
```

별도 `--dir`은 해당 폴더 안에 JSON과 collector_state를 만듭니다. 운영 기본 실행은 공개 JSON을 `site/data`, 편집 상태를 저장소 루트 `collector_state`에 둡니다. 선택적 브라우저 검사는 실행 중인 사이트의 주소를 `TOURISM_TEST_URL`로 전달할 수 있습니다. main에 직접 병합하지 않습니다.
