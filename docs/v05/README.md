### API 키 설정 방법

1. ECOS 공식 사이트의 **인증키 신청**에서 ‘약관동의 → 정보입력 → 신청완료’를 진행합니다.
   이 단계 명칭은 공식 문서에서 확인했습니다. 승인 소요시간·비용·호출 한도는 이번 조회에서
   확인하지 못했으므로 해당 서비스에서 추가 확인해야 합니다.
2. KOSIS는 <https://kosis.kr/openapi/>의 공식 인증키 절차를 접근 복구 후 확인해야 합니다.
   신청 세부 절차·요금·한도를 검증했다고 주장하지 않습니다.
3. GitHub 저장소 → **Settings → Secrets and variables → Actions → New repository secret**에
   ECOS는 `ECOS_API_KEY`, KOSIS는 `KOSIS_API_KEY`로 등록합니다. 값을 이슈/PR/채팅/JSON에 넣지 않습니다.
4. 현재 워크플로는 키 존재 여부만 사전 확인합니다. **키 등록만으로 미검증 지표가 자동 활성화되지 않습니다.**
   공식 표·항목 코드/단위·자료 상태 검증과 실제 API 어댑터 구현·실호출 검증이 후속으로 필요합니다.
   추정 코드나 샘플 키로 수치를 채우지 않았습니다.

연결한 입·출국/국적별 XLSX에는 API 키가 필요하지 않습니다. 이번 작업에서 계정 생성,
약관 동의 제출, API 신청, 외부 메시지 발송, GitHub Secret 등록을 대신 수행하지 않았습니다.

## 5. 데이터·검증·정정 처리

- `macro_sources.json`: 15개 지표의 고유 ID·정의·단위·목표 주기·기관·제공 경로·연결 여부.
  미연동 지표의 단위는 확인 전 `null`로 둡니다.
- `site/data/macro.json`: 공식 검증 시계열과 메타데이터, 최근 관측 및 비교 필드.
- `site/data/macro_health.json`: 실제 실행/수집/오류·인증 미설정/미연결/기간별 확보 현황.
- `collector_state/macro_archive.json`: 기간별 전체 수집 원장·원문 셀·파일 해시·정정 전후 이력.
- `collector_state/macro_run_summary.json`: Git에 보존되는 실행 결과. 실패도 기존 DB와 별개로 기록.
- `collector_state/macro_legacy.json`: 이전 정적 UI 값의 레거시 기록. 자동 검증 DB나 실적으로 편입하지 않음.
- `src/macro/`: 표준 라이브러리 기반 독립 XLSX 파서/수집/비교/정정/검증 엔진.

각 관측은 부모 지표 ID/정의와 함께 값·명 단위·월별 주기·기준월·기관·공식 공표문·
공표 스냅샷 시각·최초/최종 수집일·확정 상태·정정 상태·검증 방식·파일 URL/SHA·시트/셀을 갖습니다.
과거 월의 **최초 공표일을 알 수 없으면 `original_publication_at:null`**로 남깁니다.
현재 공표문 시각을 2021년 각 월의 최초 발행일로 주장하지 않습니다.

입출국 첨부는 잠정/확정을 명시하지 않아 **‘공표치 · 확정 여부 미표기’**로 표시합니다.
오래됐다는 이유로 확정으로 바꾸지 않습니다. 공식 관광수지 확정은 가이드상 익년 말에
별도 발표되지만, 이 규칙을 입출국에 임의 적용하지 않습니다.

같은 `(지표 ID, 기준월)`의 값이 달라지면 기존 값을 공식 최신 공표치로 교체하고 이전 값·
새 값·감지 시각·두 출처 해시를 이력에 보존합니다. 확정 상태만 바뀐 경우도 구분합니다.
설정된 단위·정의의 변경과 원문 단위 불일치, 이전 공표로의 회귀, 미래 월/날짜, 음수·소수 인원, 중복 월, HTML 오류 응답,
틀린 합계 행, 파일/월보 값 불일치, `명`과 `천명`의 혼동은 실패 처리합니다.

- 빈 셀은 누락이며 0으로 만들지 않습니다. 실제 0은 실제 0으로 보존합니다.
- 전월비는 **직전 달**, 전년 동월비는 **12개월 전 같은 달**로 계산합니다.
- 기준값이 0/누락이면 증감률을 계산하지 않습니다.
- 연초 누적은 1월부터 기준월까지 모두 있을 때만 계산하며, 전년 동기 누적비도 양쪽이 완전해야 합니다.
- 전부 실패/파싱 실패 시 기존 공개 DB와 원장을 바이트 단위로 보존합니다.
- 새 파일에서 과거 월이 사라져도 이전 검증값·증거를 유지하고 부분 누락 상태를 표시합니다.
- 원장 손상/유실 시 공개 일부 데이터를 정상 전체 원장처럼 재구성하지 않습니다.

실제 정정은 이번 세 번의 실호출에서 **0개**입니다. 정정·잠정→확정·실패·누락 사례는
**임시 디렉터리의 명시적 테스트 데이터**로 검증했으며 공개 DB/실수집 실적과 섞지 않았습니다.

새 `.github/workflows/macro.yml`은 매일 **12:20 KST** (`20 3 * * *` UTC),
`workflow_dispatch`와 강제 재확인을 지원합니다. 기본은 KST 달력일당 한 번이며,
강제 실행도 권한/robots/정의 검증을 생략하지 않습니다. GitHub 예약 실행은 지연될 수 있습니다.

뉴스·Research와 같은 **`tourism-pulse-publish` job 잠금**을 사용합니다. 대기 후 최신 main을
체크아웃하고 Macro 파일만 stage, `pull --rebase` 후 Push, 기존 `site` 전체를 같은 Pages 방식으로
배포합니다. 기존 두 워크플로는 변경하지 않았습니다. GitHub Pages 설정도 읽기 전용으로 확인했으며
기존 `workflow` 배포와 `https://serhankeem.github.io/tourismnews/` 주소를 유지합니다. 실제 저장 스크립트를 임시 Git 원격에서
실행해 동시 뉴스 커밋과 Macro 데이터가 새 체크아웃에도 모두 남는 것을 검증했습니다.

실패 시 이전 수치를 보존하면서 health/요약을 Git에 저장하고 진단 artifact를 남깁니다.
모든 활성 수집이 실패한 작업은 이전 자료 배포 후 실패 상태로 종료합니다.
정상 수집 후 새 공표가 없는 경우(정상·신규 0), 같은 날 아직 재수집하지 않은 경우(`not_due`),
실제 실패(`error`), 인증/정의 검증 전 미연결을 구분합니다.

## 7. 화면과 단일 DB 일치

홈 Key Indicators와 Macro Monitor는 **같은 JSON·같은 카드 렌더러**를 사용합니다.
Macro 페이지에서는 무관한 Newsroom 수집 배지를 숨기고 Macro 전용 상태를 표시합니다.
2개 연결 지표의 원 단위 정수와 기준월이 정확히 일치하며, 수입/지출은 미연동으로 표시합니다.
날짜는 KST로 표시합니다. Registry는 모든 15개 지표를 보존하고 PC에서 키보드로도 스크롤할 수 있으며 모바일에서는 페이지 흐름대로 표시합니다. 수집 실패/48시간 이상 확인 지연/장기간 최신 공표 미확인을 표시하고
기준월·마지막 검증 수치를 유지합니다. 기준월이 약 두 달 이상 경과하는 확인 경고는 서비스
점검 기준이며 기관의 공식 공표 기한을 검증했다는 뜻은 아닙니다.

차트는 실제 월 순서로 12/36/전체 기간만 선택하며 국적별 시계열도 선택할 수 있습니다.
누락 월은 ×로 구분하고 전년 자료 없는 증감률은 그리지 않습니다. 출처·단위·월간 실적·
공표/수집 시점과 정의를 표시합니다. 연간 전망은 월간 시계열에 넣지 않습니다.
현재 연결 그래프는 모두 인원 ‘명’, 축은 ‘만 명’, 증감률은 ‘%’입니다.

표시하지 않습니다.** 검토·병합 후 수동 강제 실행으로 실제 원격 저장과 공개 화면을 확인하고,
다음 일일 예약 실행과 다음 월 공표/정정을 관찰해야 합니다.

## 9. 남은 제약과 다음 단계

1. 관광수입·지출과 국제수지 여행수입·지급은 키·공식 항목/단위·잠정/확정·정정 매핑과
   실제 API 어댑터가 필요합니다. 키 등록만으로 해결됐다고 보고하지 않습니다.
2. 공개 월별 파일 연결은 현재 HTTPS 메인의 공표 링크에 의존합니다. 일반 목록의
   HTTP 리디렉션을 우회하지 않았으며, 안정적인 허용 목록/공식 수신 경로 확보가 필요합니다.
3. 데이터랩 카드 소비의 범위·이용조건, KOSIS 접근과 연간 산업조사 정의/인증은 미검증입니다.
4. 과거 전체 기간의 최초 공표일과 입출국 잠정/확정 표시는 확인하지 못했습니다.
   공표 스냅샷 시각과 `미표기`를 정직하게 보존합니다. 정의는 검토한 가이드북 버전을 기준으로 보존하며, 공식 작성방법·분류 변경은 재검토 후 전환해야 합니다.
5. 실제 정정은 이번 실행에서 없었습니다. 정정 로직의 테스트 통과와 운영 중 실제
   정정 공표를 감지했다는 사실을 구분합니다.
6. 공개 Pages 반영·원격 일일 예약 실행은 PR 병합 후 검증 과제입니다. main에 직접 병합하지 않았습니다.

python -m unittest discover -s tests -q
python -m src.macro.engine --force
python -m src.macro.report
python -m http.server 8010 --directory site
# Playwright + Chromium 환경:
TOURISM_TEST_URL=http://127.0.0.1:8010 node tests/macro.smoke.cjs
